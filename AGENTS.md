# AGENTS.md

Guidance for AI coding agents working **in this repository**. For how to *use* the extension in a build, read
[README.md](README.md) and the [docs/](docs/) folder instead.

## Project

`jeap-deployed-files-maven-extension` is a single-module Maven core extension. It provides one `EventSpy` that
records every file a build deploys to a remote repository, from the deploy events of the Maven Artifact Resolver,
and writes the list as JSON (`target/deployed-files.json`) when the build ends. Builds load it with
`-Dmaven.ext.class.path=<jar>`.

## Repository layout

```
pom.xml                                                    # Single module, packaging jar
src/main/java/ch/admin/bit/jeap/maven/deployedfiles/
  DeployedFilesEventSpy.java                               # The EventSpy: configuration, Maven events, writing the list
  DeployedFilesRecorder.java                               # Thread-safe record of the started and ended uploads
  DeployedFile.java                                        # One file of the list, built from a resolver event
  DeployedFilesJson.java                                   # Writes the JSON document by hand
  Layout.java                                              # Paths in the Maven 2 repository layout
src/test/java/...                                          # JUnit 5 unit tests, events built with RepositoryEvent.Builder
src/test/java/.../DeployedFilesExtensionIT.java            # Integration tests (maven-failsafe-plugin): real Maven deploys
src/test/java/.../MavenBuild.java                          # Starts a Maven build of a test project with the extension
src/test/resources/it-projects/<project>/                  # The Maven projects the integration tests deploy
docs/                                                      # User documentation, one topic per page
Jenkinsfile, publiccode.yml, CHANGELOG.md, LICENSE
```

## Build & test

```bash
./mvnw verify                           # unit tests and integration tests
./mvnw verify -Dit.test='DeployedFilesExtensionIT#snapshot*'   # only one integration test
```

- Parent: `ch.admin.bit.jeap:jeap-internal-spring-boot-parent`.
- `THIRD-PARTY-LICENSES.md` lists the licenses of all dependencies. Regenerate it after changing a dependency:
  `./mvnw org.codehaus.mojo:license-maven-plugin:add-third-party`.
- The integration tests (`*IT`, run by the maven-failsafe-plugin in `verify`) start real Maven builds of the projects
  under `src/test/resources/it-projects` with the packaged jar on `maven.ext.class.path`, and compare the list with
  the files in the repository. `MavenBuild` starts them as a process of the Maven that runs the build
  (`maven.home`), with its settings, local repository and proxy properties.
- Each test copies its project into a new temporary directory and deploys into a `file://` repository inside that
  copy, so the tests need no repository manager and no Docker, and a rerun without `clean` starts from an empty
  repository. Keep the repository inside the project copy. On a failure, the assertion message has the log of the
  invoked build.
- Tests are written in Java only.

## Rules for the code

- **The extension must never fail or slow down the build that loads it.** Every entry point of
  `DeployedFilesEventSpy` (`init`, `onEvent`, `close`) catches `Throwable`; only the first error is logged, as a
  warning. Do no work per event beyond what the list needs.
- **No runtime dependencies.** The jar runs on Maven's class path. Everything in `pom.xml` is `provided` or `test`;
  do not add a `compile` dependency (no JSON library, no Lombok at runtime, no utility libraries).
- **Java 25** is the oldest JDK supported: the extension is compiled with the Java version of the parent and runs
  on the JDK of the build that loads it.
- **Maven 3.9 compatibility.** The code compiles against the Maven version managed by the parent, which can be
  newer than the Maven that loads the extension. Use only API that Maven 3.9 has; that is why the deprecated
  `getFile()` accessors are used. The integration tests run on the Maven of the wrapper and guard this.
- **The JSON format is a public contract** that other tools parse. It is specified in
  [docs/deployed-files-json.md](docs/deployed-files-json.md). Adding a field is compatible; removing or renaming
  one, or changing its meaning, needs a new `formatVersion`. The user properties `deployedFiles.output` and
  `deployedFiles.skip` and the default output path are public as well.
- The component is found through `META-INF/sisu/javax.inject.Named`, generated by `sisu-maven-plugin`. Keep the
  `@Named` and `@Singleton` annotations on the event spy.
- Recording must stay thread-safe: parallel builds deploy from several threads.

## Docs

When changing public behaviour (properties, defaults, the JSON format, supported Maven versions), update the
matching page under [docs/](docs/) and the documentation index in the README. The documentation is public: link
only to public resources.

## Versioning

- Semantic Versioning; all changes documented in [CHANGELOG.md](./CHANGELOG.md) (Keep a Changelog format).
- This repository has no child modules; bump the project `<version>` in `pom.xml` directly.
- When working on a feature branch, use `x.y.z-SNAPSHOT` in the POM. Always keep the `-SNAPSHOT`
  postfix in the POM; CI removes it when releasing. Do not use the SNAPSHOT postfix elsewhere
  (CHANGELOG, publiccode.yml).
- Keep changelog entries concise and follow existing patterns.
- Keep commit messages short, use the issue ID from the branch name as a prefix, do not use
  conventional commits.
- When bumping the version, also update the changelog and update version/date in `publiccode.yml`.
- Do not put issue IDs into code, comments, configuration or documentation.
